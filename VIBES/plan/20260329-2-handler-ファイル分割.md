# handler/ ファイル分割

## 背景・目的

現在の `handler/content_handler.go` は16メソッド・662行で肥大化している。1ファイル1操作に分割し、見通しとテスト容易性を高める。

```txt
handler/content_handler.go
handler/user_handler.go
handler/favorite_handler.go
handler/other_handler.go
handler/update_data.go
```

## 注意事項

### guestID の扱い

`guestID` は現在 `user_handler.go` で定義されているが、`content_handler.go` でも参照されている（同じ `handler` パッケージなので成立）。

分割後は別パッケージになるため以下で対処する:

- `handler/user/handler.go` に `var guestID = common.GetGuestListenerID()` を定義
- `handler/content/get_top_page.go` でも `var guestID = common.GetGuestListenerID()` を定義（`common` パッケージの関数を直接呼ぶだけなので重複は問題なし）

### routing.go のimport変更

```go
// 変更前
import "github.com/sharin-sushi/0016go_next_relation/handler"
// handler.NewContentHandler(...)
// handler.Logout
// handler.GuestLogIn

// 変更後
import (
    contenthandler  "github.com/sharin-sushi/0016go_next_relation/handler/content"
    userhandler     "github.com/sharin-sushi/0016go_next_relation/handler/user"
    favoritehandler "github.com/sharin-sushi/0016go_next_relation/handler/favorite"
    otherhandler    "github.com/sharin-sushi/0016go_next_relation/handler/other"

// contenthandler.NewContentHandler(...)
// userhandler.Logout
// userhandler.GuestLogIn
```

### ファイル命名

Goの規約に合わせ snake_case を使う（`CreateVtuber.go` → `create_vtuber.go`）。

## 実装ステップ

1. `handler/content/handler.go` を作成（構造体定義）
2. content の各操作ファイルを作成（16ファイル）
3. `handler/user/` を作成（8ファイル）
4. `handler/favorite/` を作成（5ファイル）
5. `handler/other/` を作成（1ファイル）
6. `infra/routing.go` のimportとハンドラ参照を更新
7. 旧ファイル（`handler/*.go`）を削除
8. `go build ./...` でビルド確認

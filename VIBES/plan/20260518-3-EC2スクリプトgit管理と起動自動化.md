# EC2スクリプトのgit管理と起動自動化

## 背景・目的

EC2再起動・手動起動時に以下の問題が発生する:
- envファイル（api.env, app.env）がない → コンテナが起動しない
- ECR_REGISTRY等の環境変数が未設定 → docker-composeが正常に動かない

また、EC2上のbashスクリプト（`get_env_files_from_s3.bash`等）がgit管理されておらず、属人的な状態。

## 変更スコープ

- `scripts/ec2/` ディレクトリを新設
- EC2上のスクリプトをリポジトリに移管
- デプロイワークフローでスクリプトもEC2に転送
- EC2再起動時に自動で復旧できる仕組みを整備

## 実装ステップ

1. `scripts/ec2/` ディレクトリを作成
2. `get_env_files_from_s3.bash` をリポジトリに追加
3. `start.sh` を作成（ECR変数設定 + envファイル取得 + docker-compose up）
4. `.github/workflows/deploy.yml` にスクリプト転送ステップを追加
5. EC2のsystemdにEC2再起動時の自動起動を設定（またはdocker compose `restart: always`）

## start.sh の概要

```bash
#!/bin/bash
# ECR変数はEC2の ~/.bashrc で設定済みであること
# export ECR_REGISTRY=<AWSアカウントID>.dkr.ecr.ap-northeast-1.amazonaws.com
# export ECR_API_REPO=<ECRリポジトリ名（APIサービス）>
# export ECR_APP_REPO=<ECRリポジトリ名（Appサービス）>

cd ~/v-kara

# envファイル取得
bash scripts/ec2/get_env_files_from_s3.bash

# 起動
docker compose -f ec2-docker-compose.yml up -d
```

## 完了条件

- [ ] EC2再起動後に `bash scripts/ec2/start.sh` 一発でアプリが復旧する
- [ ] EC2上のスクリプトがすべてgit管理されている
- [ ] デプロイ時にスクリプトもEC2に転送される

## 注意事項

- ECR_REGISTRY（AWSアカウントIDを含む）・ECR_API_REPO・ECR_APP_REPO はpublicリポジトリにコミットしない
  - スクリプト内ではなく、EC2の `~/.bashrc` や別ファイルで管理する
- db.envはS3管理のため転送不要

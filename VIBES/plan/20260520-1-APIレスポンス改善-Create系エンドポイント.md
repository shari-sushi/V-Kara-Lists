# APIレスポンス改善: Create系エンドポイント

## 背景・目的

Issue #326「APIレスポンスちゃんとする」。Create系ハンドラがすべて `{"message": "..."}` のみを返しており、作成したリソースのデータを返していない。REST の一般的な慣習では Create 成功時に作成したエンティティを返す。

## 変更スコープ

- `t0016Go/domain/api/types.go` - Create系レスポンス型を追加
- `t0016Go/repository/interface.go` - Create系インターフェースの戻り値を変更
- `t0016Go/repository/content_repository.go` - 作成したエンティティを返すよう変更
- `t0016Go/service/content_service.go` - エンティティを上位に渡す
- `t0016Go/handler/content/create_vtuber.go` - エンティティをレスポンスに含める
- `t0016Go/handler/content/create_movie.go` - 同上
- `t0016Go/handler/content/create_karaokes.go` - 同上

フロントエンドはレスポンスを使っていないため変更不要。

## 実装ステップ

1. `domain/api/types.go` に CreateVtuberResponse, CreateMovieResponse, CreateKaraokesResponse を追加
2. `repository/interface.go` の CreateVtuber/CreateMovie/CreateKaraokes の戻り値を `(entity, error)` に変更
3. `repository/content_repository.go` の各実装を更新（GORM の `Create(&entity)` はポインタ渡しで ID が自動補完される）
4. `service/content_service.go` で戻り値をハンドラに伝播
5. 各ハンドラでレスポンスにエンティティを含める

## 完了条件

- [ ] CreateVtuber が作成した Vtuber エンティティを返す
- [ ] CreateMovie が作成した Movie エンティティを返す
- [ ] CreateKaraokes が作成した Karaoke 配列を返す
- [ ] `go build ./...` が通る
- [ ] `go test ./...` が通る

## 注意事項

- `CreateUser` (signup) はJWT返却の独自フローなのでスコープ外
- GORM の `db.Create(&entity)` はポインタ渡しなので実行後に `entity.ID` が自動設定される

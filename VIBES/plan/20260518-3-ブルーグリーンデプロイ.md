# ブルーグリーンデプロイ導入

※AWS EC2 t3.microで、alb廃止しcaddy app, api, mysqlを詰め込む予定であるため、この計画は一時中止。恐らくスペック不足となるため。

## 背景・目的

現在、EC2 で `docker-compose up -d` を実行するとコンテナが再起動する数十秒間、port 80 が無応答になりブラウザがスピナーのまま止まる。更新でエラーが起きると一生止まる。

ブルーグリーンデプロイを導入し、ユーザーへのダウンタイムをゼロにする。

## 方針

同一 EC2 内でブルーグリーンを実現する（追加コストなし）。

```
[ブラウザ]
    ↓
[nginx] ← 常時稼働。port 80 / 8080 を受け持つ
    ↓ upstream.conf で切り替え
[app-blue or app-green]
[api-blue or api-green]
    ↓
[db] ← 共有。変更なし
```

切り替えは `nginx -s reload` で行う。reload はリクエストを切らずにワーカーを入れ替えるため、ダウンタイムゼロ。

## 変更スコープ

### 新規作成

- `nginx/conf.d/default.conf` — nginx の静的設定（proxy_pass 先を upstream 名で参照）
- `nginx/conf.d/upstream.conf` — active slot を指定（deploy.sh が書き換える）
- `nginx/html/maintenance.html` — upstream が全滅したとき用のフォールバックページ
- `deploy.sh` — ブルーグリーン切り替えスクリプト（EC2 上で実行）

### 変更

- `ec2-docker-compose.yml`
  - `app` / `api` を `app-blue` / `app-green` / `api-blue` / `api-green` に分割
  - Docker Compose profiles (`blue` / `green`) で起動セットを制御
  - `nginx` サービスを追加（port 80 / 8080）
  - `db` はそのまま（共有リソース）

## 実装ステップ

1. `nginx/conf.d/default.conf` を作成
2. `nginx/conf.d/upstream.conf` を作成（初期値: blue）
3. `nginx/html/maintenance.html` を作成
4. `ec2-docker-compose.yml` を書き換え
5. `deploy.sh` を作成
6. README / deployment.md にデプロイ手順を追記

## EC2 での初回移行手順

```bash
# 1. 旧コンテナを停止
docker-compose -f ec2-docker-compose.yml down

# 2. nginx + db + blue を起動
docker-compose -f ec2-docker-compose.yml --profile blue up -d

# 3. ヘルスチェック確認後、完了
```

## デプロイ手順（以降）

```bash
# EC2 上で実行するだけ
./deploy.sh
```

## 注意事項

- Next.js は `ENV PORT=80` で動いているので、内部ポートはそのまま 80 を使う
- Go API も内部ポート 8080 を維持（コンテナ名が違うのでホスト競合しない）
- `api.env` / `app.env` は blue/green 両方で共有する（同じ env_file を参照）
- `nginx -s reload` は graceful reload なので既存接続を切らない

# PR自動レビュー・自動マージ

新規PR（ベースブランチは問わない）を検出し、レビュー〜マージまでを自動で行う。
自分（親）のコンテキストは温存し、PRごとの実際のレビュー作業は子エージェントに委任する。

## 親が行うこと

1. `gh pr list --state open --json number,title,baseRefName,isDraft,labels,url` でオープンPRを取得する（ベースブランチは絞り込まない）。
2. ドラフトPR、既に `claude-reviewed` ラベルが付いているPRを除外する。
3. 対象PRが無ければ「新規PRなし」とだけ報告して終了する。
4. 対象PRが複数ある場合は、PRごとに Agent ツール（subagent_type: general-purpose, isolation: "worktree", run_in_background: true）を並列で起動する。各Agentへのプロンプトには以下を自己完結する形で含める（Agentは今回の会話の文脈を持たないため、必要な情報は全てプロンプトに書く）:
   - 対象PR番号・URL
   - `/code-review` スキルでそのPRをレビューすること
   - 判定基準:
     a. correctnessカテゴリの指摘が0件、かつ「マージ後の修正が難しい」指摘が0件 → 問題なしと判断し `gh pr merge <番号> --squash` でマージする
     b. 上記のうち「マージ後でも簡単に直せる」軽微な指摘がある場合は、指摘ごとに `gh issue create` でissueを立て、issue番号を記載したコメントをPRに残してからマージする
     c. correctnessの指摘がある、または重大でマージ後修正が難しい指摘がある場合はマージせず、レビュー内容をPRにコメントし、人間の確認が必要な旨を明記する
   - いずれの場合も処理後に `.claude/commands/scripts/pr-label.sh add <番号>` で `claude-reviewed` ラベルをPRに付与する（ラベル未作成時の `gh label create` もスクリプト側で自動的に行う）
   - issueやPRコメントの末尾には CLAUDE.md の規約通り `🤖 Generated with [Claude Code](https://claude.com/claude-code)` を付ける
   - 作業（マージ or issue化 or 人間確認コメント）が完了したら、その時点でAgentの役目は終わりであり、それ以上何もしなくてよい（結果を簡潔に報告して終了する）
5. 全Agentを起動したら、親はその場で完了を待たずに「今回起動したPRレビューの一覧（PR番号・タイトル）」を短く報告して今回のサイクルを終える。各Agentの結果は完了通知として後で届くので、届いたら「PR#番号: 結果」の形で一言だけ報告する。
6. `gh` コマンドが失敗した場合(認証切れ等)は、エラー内容を報告してループを止めるかどうかユーザーに確認する。

## 監視ループの運用

- 継続監視が必要な場合、ループは **このセッション内**（`/loop` または `CronCreate` によるセッション内スケジュール）で回す。セッションを閉じれば停止する前提とし、クラウド常駐スケジュール（`/schedule`）は明示的に依頼された場合のみ使う。
- 親（このコマンドを実行している自分）はサイクルごとに「PR検出 → 子エージェント起動 → 起動一覧の報告」だけを行い、レビューやマージの実作業自体には手を出さない。実作業は必ずPRごとの子エージェント（worktree isolation）に委任する。
- 子エージェントが権限classifierにブロックされる、判断に迷う、あるいはユーザー確認が必要な状況に行き当たった場合は、子エージェント自身がユーザーに確認を取ろうとするのではなく、親に状況を返す。親がその場でユーザーに確認し（`AskUserQuestion` 等）、判断結果を子エージェントに `SendMessage` で指示として返して作業を継続させる。親の役割はあくまで「指示出しと報告」であり、子エージェントに代わってレビュー内容を精査したり `gh` コマンドを直接実行したりはしない。

## 注意

- 対象PRのベースブランチは問わない（develop以外向けPRも対象）。
- マージ方式は squash 固定。
- 一度 `claude-reviewed` ラベルが付いたPRは再レビューしない（同一PRの二重マージ防止）。

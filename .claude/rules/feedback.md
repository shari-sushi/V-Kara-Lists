# フィードバックシステム

AIのミスや改善点を蓄積・学習するための仕組み。レビューで受けた指摘を「二度繰り返さない」ためのループを回す。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| [feedback/log.md](../feedback/log.md) | ユーザー／レビューが指摘したAIのミスを時系列で記録（append-only） |
| [feedback/lessons.md](../feedback/lessons.md) | log.md から蒸留したパターン化された教訓（常時読み込み） |

## log.md への記録ルール

ユーザーやレビューからミスの指摘を受けたとき、**会話終了前に必ず** `log.md` に追記する。
既存エントリは編集・削除しない（append-only）。

```markdown
## YYYY-MM-DD: [ミスのタイトル]（PR #N）

**カテゴリ**: design / code-quality / architecture / ux / process / other
**状況**: どんな作業・変更をしていたか
**ミス（指摘）**: 何をやってしまったか
**正解 / 対応**: 何をすべきだったか・どう直したか
**なぜセルフレビューで見つからなかったか**: 一次原因（次回 lens を増やすために必須）
```

- 日付は会話中の「今日の日付」を絶対日付で書く。
- 実害が無い指摘（コメントのズレ・疑問）も省略しない。将来の蒸留材料になる。

## lessons.md への蒸留ルール

`log.md` に**同じカテゴリのミスが3件以上**たまったら、パターンを抽出して `lessons.md` に追記し、
該当する log エントリに `[distilled]` タグを付ける。

- lessons.md の各項目は「**ルール — 理由**」の形式で書く。
- 蒸留した教訓は `self-review.md` のチェックリストにも反映を検討する（次回セルフレビューで先回りできるようにする）。

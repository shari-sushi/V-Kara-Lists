# DBバックアップ自動化（差分検出・世代管理・S3保存）

## 背景・目的

EC2上のDockerMySQLには自動バックアップがない。差分があった場合のみS3へ保存し、世代管理によってコストを抑えつつ復元可能な期間を確保する。

## 保持ポリシー

| 世代 | 保持期間 | S3プレフィックス |
| --- | --- | --- |
| 日次 | 30日 | `daily/` |
| 月次（毎月1日） | 1年 | `monthly/` |
| 半年次（1月1日・7月1日） | 5年 | `semiannual/` |

## 変更スコープ

| ファイル | 変更内容 |
| --- | --- |
| `scripts/db-backup.sh` | バックアップスクリプト（新規） |
| ~~`ec2-docker-compose.yml`~~ | ~~`backup` サービス追加~~ |
| `infra/terraform/s3.tf` | S3ライフサイクルルール追加 |

EC2 cron + `docker exec` で実行するため docker-compose の変更は不要。

## 差分検出の仕組み

1. `--skip-comments` オプションでダンプ → md5ハッシュを計算（比較用）
2. S3の `latest.md5` と比較
3. 差分あり → 通常ダンプ（日時コメントあり）をS3にアップロード、`latest.md5` を更新
4. 差分なし → スキップ

月次・半年次の判定はアップロード時の日付で行う（毎月1日 → `monthly/` にも保存、1月1日・7月1日 → `semiannual/` にも保存）。

## 実装ステップ

1. `scripts/db-backup.sh` を作成
2. ~~`ec2-docker-compose.yml` に `backup` サービスを追加~~ → EC2 の crontab にスクリプトを登録
3. `infra/terraform/s3.tf` にライフサイクルルールを追加
4. ~~ローカルで動作確認（dockerネットワーク経由でdumpできるか）~~ → EC2上で動作確認（`docker exec` 経由でdumpできるか）

## 完了条件

- [ ] 差分なし時はS3にアップロードされない
- [ ] 差分あり時は `daily/` にアップロードされる
- [ ] 毎月1日は `monthly/` にも保存される
- [ ] 1月1日・7月1日は `semiannual/` にも保存される
- [ ] S3ライフサイクルで各世代が正しく削除される

## 注意事項

- ~~バックアップコンテナにはAWS認証情報（EC2 IAMロール経由）が必要。`api.env` にクレデンシャルを追加しない~~ → EC2上で直接実行するためIAMロールが自動的に使用される。認証情報の追加設定は不要
